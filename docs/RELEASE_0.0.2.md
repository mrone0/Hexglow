# Hexglow 0.0.2

本版补齐可选的自动模型推荐、API Key 持久化，并修复模型结果已生成但悬浮侧栏没有重新展开的问题。推荐仍由用户配置的模型结合当次上下文和知识库动态判断，不加入固定英雄/海克斯适配分。

## 本版变化

- 设置新增“自动模型推荐（可能产生费用）”，默认关闭。开启前需要授权当前模型服务；自动授权绑定服务地址及模型，更换后需重新开启。
- 游戏前台连续两次稳定识别到同一组完整三张 OCR 候选后，才自动分析。手动候选仍需主动点击分析；OCR 识别本身不调用模型。
- 同一组候选在本次运行中不自动重复请求，已发出的请求失败也不自动重试。本次应用运行中每轮最多 3 次自动请求，与手动分析共用每日上限和请求间隔。已保存的同组分析可在重启后阻止重复自动请求。
- 模型分析期间继续采集和识别，但不并发发送自动请求。候选、轮次、对局、模型授权或知识变化后，旧响应不弹回当前侧栏；有效结果保存成功后才发布并展开侧栏。
- 修复稳定识别的边界判断：名称或效果变化、识别中断、暂停与恢复跟踪都需要重新确认，不能把发送前检查当成新的一帧 OCR。
- API Key 按协议和服务地址保存在当前 Windows 用户的凭据管理器中，重启、正常升级或切回服务时自动恢复。输入后自动保存，清空输入框会删除该服务的密钥；退出与更新会等待密钥保存完成。密钥不会写入普通设置、对局档案、导出文件或日志。

局势、装备或知识变化本身不会为已请求的同组候选额外触发模型调用。关闭自动推荐立即停止新的自动调用；已发出的请求可能仍产生费用。

## 安装与升级

1. 已安装 `0.0.1` 的用户，可在本 Release 资产发布完成后使用“设置 → 应用更新”检查并安装 `0.0.2`，无需先卸载。
2. 也可下载 `Hexglow_0.0.2_x64-setup.exe`，先保存资料并从应用内“完全退出”，再沿用原目录覆盖安装。不要勾选删除应用数据。
3. 正常覆盖安装与内置更新保留知识库、对局档案、设置与已保存的密钥。旧包没有保存过的 Key 无法恢复，请在本版中重新填写一次，看到“密钥已保存”后即可在之后的启动与升级中恢复。自动推荐默认不开启，升级不会自动增加模型费用。
4. 早期版本号高于 `0.0.2` 的开发包不会自动降级；需要手动覆盖安装。请使用完整安装包，不要仅复制 EXE，以免缺少离线 OCR 资源。

此 Release 按维护者要求重新发布了 `0.0.2`。已经安装此前 `0.0.2` 包的用户，需要下载本 Release 的新安装器覆盖一次，内置更新不会提示相同版本号的替换。`0.0.1` 用户可正常检查更新。

更新前先保存知识编辑，在下载与安装期间不要继续编辑未保存资料。发布资产包含安装器、`.sig`、`latest.json` 和 `SHA256SUMS.txt`，沿用现有更新签名公钥；私钥不会包含在安装包中。更新签名不等于 Windows 发布者证书，Windows 仍可能显示未知发布者或 SmartScreen 提示。

## 验证与边界

本次本地验证：501 项前端与脚本测试、181 项 Rust 测试、TypeScript/Vite 构建及 Rust 格式检查通过；1 项需要可见游戏窗口的测试未执行。覆盖自动请求、费用限制、授权撤回、候选变化、结果发布竞态、密钥切换服务和保存退出等待，并以独立合成记录验证 Windows 凭据的真实写入、读取、覆盖与删除。测试没有调用真实付费模型，也没有操作游戏、个人凭据或真实对局数据库。GitHub Actions 另行执行测试、Windows 安装器构建及更新签名验证；以对应运行结果为准。

本次自动推荐尚未完成安装后的真实模型端到端验收。OCR 匹配数量不代表逐字准确，模型比较分不是胜率，也不保证最优选择。活动对局退出、线上自动更新、全部分辨率和游戏补丁等场景仍有未验范围。赛后接口可能仅提供部分数据，不能据此声称业务记录全员、全轮次齐全。
