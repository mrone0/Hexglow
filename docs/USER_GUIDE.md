# 使用说明

[返回 README](../README.md) · [本地打包](BUILDING_WINDOWS.md)

## 功能

- 自动发现 LoL 客户端，展示大厅、选人、对局和结算状态。
- 在游戏前台时通过截屏 OCR 识别海克斯候选，支持手动补充和纠正；识别模型随安装包提供，启动即在后台预热，无须配置 Key 或首次下载模型。
- 识别后展示本轮候选，通过 Jev 或 OpenAI 兼容模型动态分析。自动推荐首次默认开启，但只有模型配置有效并授权当前服务后才会调用（可能产生费用）；也可手动分析。开关、服务地址和模型名称会保存，手动关闭会记住。同一份模型结果可在主窗口和悬浮侧栏查看。
- 保存对局快照、推荐依据、实际选择和赛果，支持档案查询、删除与 JSON 导出。
- 在知识工坊用中文表单编辑英雄和海克斯资料，保存后用于后续分析；保留高级 Markdown 编辑。
- 关闭主窗口后继续在系统托盘运行；重复启动会打开已有窗口，避免同时运行多份采集进程。

模型分析和悬浮侧栏均只提供参考，不自动点击或替玩家选择。

## 使用

1. 启动 LoL 和 Hexglow。应用会自动尝试连接本地客户端；发现失败时，可在设置中填写 lockfile 的绝对路径。
2. 进入对局后查看英雄和双方阵容。游戏位于前台、可见且非最小化时，应用自动识别候选；识别不到时，在高级区域补充名称和完整效果。
3. 检查候选和已选海克斯。手动纠正会保留至当前选择轮次结束；点击“重新识别候选”可恢复读取当前画面。
4. 在设置中配置模型服务、模型名称和密钥，再授权发送数据。自动推荐首次默认开启，配置及授权有效后，新一组完整三张候选连续两次识别稳定才自动分析；不希望自动调用时请在授权前关闭“自动模型推荐（可能产生费用）”。开关与模型配置在重启、正常升级后恢复；以前保存过关闭状态的用户继续保持关闭。更换服务仍需重新授权，不向未授权地址发送数据。识别本身不调用推理服务；同局同轮同候选的已生成结果会保留，装备或局势变化时标注为此前快照，不自动重复扣费，必要时可手动刷新。重启后可从档案恢复同组已有模型结果；换局、换轮、候选或本人选择变化后不沿用。
5. 选择海克斯后记录实际选择；赛后可补充观察并生成复盘。档案页可查看、删除或导出记录。

对局进行中，他人的海克斯通常不可得，按未知处理；赛后应用按对局 ID 从本地结算及比赛历史接口限次补录。赛果只有在证据明确且能归属到该局和本人时才自动标记，断线不代表失败。档案页的「重新补录结算」可重试未完成的补录，接口不提供的内容仍保留未知。

赛后条目的「已核实」仅表示已有条目完成归属，不证明全员、全部轮次齐全。后台补录在结束后 10 分钟内最多尝试 8 次，期间可继续合并可信的分批证据；不会因为每人已有一条记录就提前结束，也不会为了凑齐固定数量补造选择。已有自动赛果和首份原始结算证据不会被后续矛盾或空响应覆盖。

点击窗口右上角“×”只隐藏主窗口，采集仍在后台运行。单击系统托盘中的 Hexglow 图标可恢复窗口；要停止采集并完全退出，请右键托盘图标，选择“退出 Hexglow”。退出前会保存当前对局，保存失败时保留应用并显示提示。

## 推荐方式

新推荐由模型依据当次英雄、装备、双方阵容、已知海克斯、完整候选效果和检索到的知识动态比较，不注入或混合固定英雄/海克斯适配分。Jev 使用 `self`、`allies`、`opponents` 表示当前英雄、队友和敌方，不发送 `ownPlayerId` 或玩家 ID，也不检索或发送 `history`；普通语言模型通道仍可附带相关历史摘要。打包字典只用于识别、精确身份关联和已拥有去重，不能代替真实机制证据。已拥有候选不参与有效推荐；知识缺失或机制不明时保留不确定性，不把未知当作不适配。

阵容不是发起候选分析的硬门槛：只有本人、部分阵容或暂未读到玩家列表时，也可基于已提供的候选效果与知识分析。后端明确标注上下文可用性，不从列表顺序、旧对局或知识文档猜当前英雄/队伍；缺失的对应维度保持未知。已知英雄和装备仍可参与比较，若证据不足则展示有限信息结果而非编造可信评分。阵容补齐不会对同局同轮同组候选自动再次收费；原分析只作为标注过的此前快照，需要时手动刷新。记录“我选了”仍要求可确认的本人身份和实际轮次。

模型根据英雄协同、出装协同、队伍适配和敌方适配四项因素返回分数与置信度：

- 各因素按置信度计算模型分；零置信度或缺失置信度的因素不参与均值。
- 按四项平均置信度，将模型分向中性 50 分收缩，不采用本地规则先验。
- 全部因素未知时内部结果为 50；证据或置信度不足的候选组不显示分数和推荐名次。
- 旧档案保留生成时的公式和结果，不自动重算；新结果标记为 `dynamic-model-v1`。

结果是 0–100 的相对契合度，不是胜率。Jev 服务置信度与普通模型自报置信度分别标记，均未按真实对局校准。提供给模型的参考文档不等于模型实际引用；模型返回的引用只接受本次提供的文档路径及有效章节，引用匹配也不代表解释已被事实核验。

历史档案保留在本地供查看和复盘；Jev 不读取其他对局作为参考，显式复盘仅使用目标对局已记录的决策与结算。普通语言模型通道保留相关历史检索，应用不自动训练模型权重。内部玩家标识仍用于实时采集、本人选择关联与保存，不因外发精简而删除本地记录。

详细匹配规则、评分公式和修复说明见 [算法匹配文档](ALGORITHM_MATCHING.md)。

## 知识工坊

左侧“知识工坊” → 选择英雄或海克斯 → 在默认表单中修改名称、说明和各段知识 → 保存资料。无需编辑 YAML、内部编号或文件路径；适用版本、资料状态、别名和标签可在“辅助信息”中填写。保存时自动校验格式，不会自动调用模型。

表单编辑与高级编辑共享同一份未保存内容；未修改的元数据、自定义章节和链接原样保留。不能安全映射的复杂文档会保留原文并提示使用高级编辑，不会擅自重建。高级编辑保留原始 Markdown 编辑、导入和安全文本预览。海克斯资料可新建和删除，新建编号自动生成；导入新海克斯时按文件内的合法编号定位，但不会静默覆盖已有资料。英雄资料禁止删除。

资料状态显示为“待核实 / 已整理 / 已过时”，仅是维护标记；“已整理”不代表自动核验，“已过时”也不会自动排除检索。切换分类、对象或页面，以及正常完全退出前，会保护未保存的编辑；保存失败时保留输入以便重试。

文档路径采用 `champions/ahri.md` 或 `augments/custom-example.md`；身份字段和路径必须符合校验规则。每份文档保存时最多保留 3 份备份。种子升级只更新内容仍与旧生成版本精确匹配的文档，保留用户编辑和删除。

当前种子覆盖 173 位英雄和 211 个海克斯，另附虚构模板。**种子均未经游戏内核验，英雄技能与交互机制仍不完整。** 文档格式、必填字段和章节约定见 [OKF Profile](../knowledge-seed/README.md)。

分析按英雄、候选和已选海克斯精确检索，并沿一层文档链接补充，最多提供 16 份文档、64 KiB 内容。超预算时按章节裁剪；缺失、版本差异、裁剪及不可读取的文档会显示提示。

知识正文作为模型本次判断的参考，不会被编译为固定适配分。编辑或保存知识不会自动调用收费模型；下一次手动分析或满足自动推荐条件的分析会读取更新。局势、装备或知识变化以及侧栏重开都不会额外触发自动请求。

自动推荐只在新一组完整三张候选连续两次识别稳定后触发。同一组候选在本次运行中不自动重复请求，失败也不自动重试；本次应用运行中每轮最多 4 次自动请求，覆盖初始候选和三张卡各一次刷新；不设每日总上限。模型分析期间，实时采集与候选识别继续，不会并发发起自动模型请求；过时的分析结果不会作为当前候选推荐弹回侧栏。需要重新分析时可手动操作，仍受请求防抖约束。关闭自动推荐立即停止新的自动调用；已发出的请求可能仍产生费用。自动推荐不会操作游戏或替玩家选择。

OCR 按海克斯选择阶段调度：开局、7／11／15 阶段的实际信号会立即唤醒扫描，不继承上一阶段等待。真实面板出现后，短时漏读仍快速复核，持续缺失再降为低频探测；缺失不是“已经选完”的证据。两次真实稳定识别仍至少间隔 500ms，完整面板后的额外空闲为 350–700ms，最近出现过面板的漏读额外等待 700ms。推理耗时另计，不代表 700ms 内出评分。

同组候选的专用快速复核最多安排 4 次、窗口 6 秒，普通扫描仍独立于客户端 API 轮询。发现窗口、12 秒漏读宽限及低频策略见 [OCR 调度记录](OCR_PERFORMANCE.md)。游戏不在前台、最小化或识别异常时仍暂停或退避，不并发截图或推理；250ms 的后台唤醒只检查是否到期，不等于每 250ms 扫描。推理与预处理保持低优先级受限线程池，关闭空闲自旋。

自动识别先检查整段卡片边缘，排除自有侧栏的遮挡边界；边框不可靠时尝试三个对齐的卡片内部区域。OCR 优先只读标题条带，遮掉卡片间空隙，必要时只在卡片内部回退，不识别周围游戏文字。两种区域定位都未成功时继续轻量探测，不生成候选或调用模型；已有侧栏标为“此前候选 · 复核中”，暂不显示旧评分和综合推荐，不因两次定位不确定就关窗。持续未确认约 3 秒、且鼠标没有停在侧栏内时折叠成把手，保留候选和结果，不据此认定已选择完成；真实同组 OCR 恢复时清除复核状态，不强行展开旧窗口。一般无交互折叠仍为 20 秒。新样式或严重遮挡仍可能无法定位。统计页将探测与完整推理分开显示；历史命中次数不等于面板内识别准确率。

本组已分析或已尝试后、没有模型分析在途时，允许轻量比较真实识别出的标题区域：像素变化就重识别，不变最多 3 秒后仍重新检查卡片。轻量检查不算 OCR 证据、不调用模型，也不关闭已显示推荐；刷新后仍需两次新鲜识别。未知布局等待重新定位，不回扫整片游戏画面。侧栏评分更新不再反复调整窗口或重启悬停监听，重复关闭也会去重。此优化降低重复工作，不保证零掉帧。

漏读仍清除稳定证据，必须重新读到两次完整同组候选才允许新请求，不拼接旧卡片。每组新候选还需一次识别之后发起的、同局同轮的新客户端采集确认，防止升级换轮时误用旧轮次重复付费；超过 5 秒没有新快照则暂停扫描。游戏不在前台、识别报错或复核窗口过期时停止快速复核。模型在途时，单次空帧只在最后完整识别后 2 秒内允许同组已返回结果更新侧栏，不重新开窗；连续漏读、换组或换轮后不发布旧结果。侧栏分别显示候选复核、轮次同步、模型分析、评分返回后的保存同步状态；这些等待不等于模型推理耗时。上述节奏是调度规则，不是实战帧率或端到端响应时间保证。

确认对局、选英雄、载入、重连与进行中按客户端阶段安排约 1 秒后的下一次采集；加载多久都不按时间猜开局。LCU 阶段、会话与 Live API 并行读取，共用连接；完整 Live 数据等待最多 500ms。LCU 已进入进行中、同局身份有效但缺开局事件时，补读 Live `/eventdata`，最多等待 250ms。HTTP 成功或 LCU 的载入阶段本身不等于实际开局。认证成功更新客户端缓存，失败则使旧凭据失效。

首轮由当前局实际 `GameStart` 事件唤醒，不额外等待 3 级或完整阵容；缺等级时还须本次运行确实观察过该局的选人／加载过程。重启恢复旧档案不算新开局。后续使用实际 7／11／15 等级阶段，已经进入后续阶段却暂时缺等级时等待接口恢复，不退回首轮。内部首轮编号仍为 `1`，不是伪造玩家等级。仍须实际识别候选才显示侧栏；上述等待预算及调度间隔不是端到端响应承诺。

OCR 和本地知识在应用启动时后台预热，并在选人／加载阶段提前检查，无需等候选出现；同时准备查询表及隐藏、不抢焦点的侧栏。自动扫描先检查推理引擎是否就绪：未就绪直接返回预热状态，不截屏、不排队等初始化锁，并在约 250ms 后再检查。已就绪不重复预热，忙碌不消耗两次真实失败重试预算；初始化失败明确显示错误。准备工作不调用模型、不消耗分析次数，也不猜候选评分。正式知识检索仍校验文档内容哈希，外部编辑、新增或删除资料可在下一次检索生效。预热失败不阻断客户端采集；实时信息仅来自实际接口观测。

OCR 使用 PP-OCRv6 Small 检测配合 Tiny 文字识别；布局消歧、三项名称精确匹配及标题置信度均不低于 0.95 才走快路。Small 回退整组替换、不拼接结果；自动扫描完全无线索时限频回退，保留每阶段及至少 6 秒间隔的安全检查。截取客户端居中 90% 宽、52% 高仅用于像素定位，并遮挡自有侧栏；实际送入 OCR 的只有标题区域或三张卡片内部。手动截屏同样遵循这个范围，开发图片检查保留原图管线。两次真实稳定识别门槛不变，置信度不等于实际正确率。预热仅用内置合成图片，扫描使用低优先级受限线程。具体预算、离线基准及局限见 [OCR 性能验证](OCR_PERFORMANCE.md)。

## 模型与隐私

支持 TypeSafe Jev 和 OpenAI 兼容服务，包括第三方 HTTPS 服务，以及 Ollama、LM Studio 等本机 HTTP 服务。连接测试读取模型列表，实际推理能力需要通过分析请求确认。使用第三方 Jev 地址需在设置中明确允许。

- API Key 按协议与服务地址保存在当前 Windows 用户的凭据管理器中，启动或切回服务时自动恢复；不写入普通设置、档案或日志。输入后自动保存，清空输入框删除该服务保存的密钥，保存状态会显示在设置页。正常升级沿用同一份凭据；地址和模型等非敏感设置也可持久化。
- 外发前去除原始 Live、LCU 和结算数据、玩家名称与对局 ID；保留英雄、海克斯及相关知识。Jev 还移除玩家 ID 和跨局历史摘要，普通语言模型通道可保留历史观察。自由文本可能含个人信息，发送前请检查。
- 模型请求最多 256 KiB 上下文、1 MiB 响应，超时时间 30 秒。
- 同时只允许一次分析；真实发送之间至少间隔 1 秒，同组候选的手动重复分析（或同局重复复盘）至少间隔 8 秒。新组候选、新轮和新局不继承上一组的 8 秒限制；本地知识准备失败或发送前取消不消耗请求间隔。不设每日总上限，今日次数仅作统计；已发出的失败请求也计入本轮自动次数；同组不自动重试、每轮最多 4 次自动请求（初始候选加三张卡各一次刷新）。
- 应用没有遥测、远程字体或云端回退。模型服务可能产生费用；本地服务是否联网由该服务自身决定。

严格离线使用需要准备本地推理服务与依赖，并限制该服务的出站网络。应用的回环地址限制不能阻止模型服务自行转发数据。

## 档案与日志

档案保存在应用数据目录的 `sessions.sqlite3`，运行日志页显示实际路径。应用标识为 `ai.hexglow.desktop`。数据库未额外加密，备份和共享时请注意玩家信息。

每页显示 50 条轻量摘要，完整档案按需读取。记录包含阵容、候选、推荐结果及当时的决策上下文、实际选择、阶段时间线、原始采样、赛果证据和复盘。接口没有提供的字段保持未知。

设置页可查看存储用量和执行维护：默认预算 128 MB，可设 32–2048 MB；原始采样默认保留 7 天，可设 1–365 天，每局最多 30 份。空闲时每 30 分钟检查维护，优先清理过期采样与旧原始快照，决策证据、选择和复盘不自动删除。预算是写入保护，不是严格的物理文件大小上限。

常规自动落盘间隔为 60 秒，阶段变化和对局结束会及时保存；异常退出可能丢失最近约一分钟的未落盘采样。异常档案单独隔离并提示，全部历史导出会保留其原文。导出文件写入应用数据目录的 `exports/`，界面显示完整路径。

运行日志采用脱敏 JSONL，不记录令牌、玩家姓名或模型上下文，当前与上一份日志合计最多 1 MiB。识别统计区分真实截屏与开发样本，不统计相同画面的缓存复用和跳过的截屏。
