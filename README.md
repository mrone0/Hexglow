# 海萤 · Hexglow

> **AGPL-3.0-only 开源项目。开源不是放弃版权。** 商用允许，但分发及修改版网络服务必须依法履行对应的开源、许可与声明义务；禁止违反许可的闭源分发及冒充官方。请先阅读 [开源许可与使用声明](OPEN_SOURCE.md) 和 [完整许可证](LICENSE)。

**让每一次选择，都有微光指引。**

Hexglow 是面向 Windows 的本地海克斯大乱斗决策辅助应用，使用 Tauri 2、Rust、React/TypeScript 和 SQLite。它读取本地客户端接口与游戏画面，结合当前英雄、阵容、已选海克斯和知识文档，提供候选分析与赛后复盘。当前版本为 **0.0.2**，变更和安装说明见 [版本说明](docs/RELEASE_0.0.2.md)。

## 功能

- 自动发现 LoL 客户端，展示大厅、选人、对局和结算状态。
- 在游戏前台时通过截屏 OCR 识别海克斯候选，支持手动补充和纠正；识别模型随安装包提供，启动即在后台预热，无须配置 Key 或首次下载模型。
- 识别后展示本轮候选，默认手动调用 Jev 或 OpenAI 兼容模型动态分析；也可在设置中单独开启自动模型推荐。同一份模型结果可在主窗口和悬浮侧栏查看。
- 保存对局快照、推荐依据、实际选择和赛果，支持档案查询、删除与 JSON 导出。
- 在知识工坊用中文表单编辑英雄和海克斯资料，保存后用于后续分析；保留高级 Markdown 编辑。
- 关闭主窗口后继续在系统托盘运行；重复启动会打开已有窗口，避免同时运行多份采集进程。

模型分析和悬浮侧栏均只提供参考，不自动点击或替玩家选择。

## 使用

1. 启动 LoL 和 Hexglow。应用会自动尝试连接本地客户端；发现失败时，可在设置中填写 lockfile 的绝对路径。
2. 进入对局后查看英雄和双方阵容。游戏位于前台、可见且非最小化时，应用自动识别候选；识别不到时，在高级区域补充名称和完整效果。
3. 检查候选和已选海克斯。手动纠正会保留至当前选择轮次结束；点击“重新识别候选”可恢复读取当前画面。
4. 需要推荐时，在设置中配置模型服务并授权发送数据，然后手动点击分析；若希望识别后自动推荐，再单独开启“自动模型推荐（可能产生费用）”。自动推荐默认关闭，授权绑定当前服务和模型，切换后需重新开启。识别本身不调用推理服务；分析成功且仍属于当前上下文时，会打开侧栏显示同一份模型结果，不额外发起请求。
5. 选择海克斯后记录实际选择；赛后可补充观察并生成复盘。档案页可查看、删除或导出记录。

对局进行中，他人的海克斯通常不可得，按未知处理；赛后应用按对局 ID 从本地结算及比赛历史接口限次补录。赛果只有在证据明确且能归属到该局和本人时才自动标记，断线不代表失败。档案页的「重新补录结算」可重试未完成的补录，接口不提供的内容仍保留未知。

赛后条目的「已核实」仅表示已有条目完成归属，不证明全员、全部轮次齐全。后台补录在结束后 10 分钟内最多尝试 8 次，期间可继续合并可信的分批证据；不会因为每人已有一条记录就提前结束，也不会为了凑齐固定数量补造选择。已有自动赛果和首份原始结算证据不会被后续矛盾或空响应覆盖。

点击窗口右上角“×”只隐藏主窗口，采集仍在后台运行。单击系统托盘中的 Hexglow 图标可恢复窗口；要停止采集并完全退出，请右键托盘图标，选择“退出 Hexglow”。退出前会保存当前对局，保存失败时保留应用并显示提示。

## 推荐方式

新推荐由模型依据当次英雄、装备、双方阵容、已知海克斯、完整候选效果、检索到的知识和相关历史动态比较，不注入或混合固定英雄/海克斯适配分。打包字典只用于识别、精确身份关联和已拥有去重，不能代替真实机制证据。已拥有候选不参与有效推荐；知识缺失或机制不明时保留不确定性，不把未知当作不适配。

模型根据英雄协同、出装协同、队伍适配和敌方适配四项因素返回分数与置信度：

- 各因素按置信度计算模型分；零置信度或缺失置信度的因素不参与均值。
- 按四项平均置信度，将模型分向中性 50 分收缩，不采用本地规则先验。
- 全部因素未知时内部结果为 50；证据或置信度不足的候选组不显示分数和推荐名次。
- 旧档案保留生成时的公式和结果，不自动重算；新结果标记为 `dynamic-model-v1`。

结果是 0–100 的相对契合度，不是胜率。Jev 服务置信度与普通模型自报置信度分别标记，均未按真实对局校准。提供给模型的参考文档不等于模型实际引用；模型返回的引用只接受本次提供的文档路径及有效章节，引用匹配也不代表解释已被事实核验。

历史档案用于检索相关经验和复盘参考，应用不自动训练模型权重。

详细匹配规则、评分公式和修复说明见 [算法匹配文档](docs/ALGORITHM_MATCHING.md)。

## 知识工坊

左侧“知识工坊” → 选择英雄或海克斯 → 在默认表单中修改名称、说明和各段知识 → 保存资料。无需编辑 YAML、内部编号或文件路径；适用版本、资料状态、别名和标签可在“辅助信息”中填写。保存时自动校验格式，不会自动调用模型。

表单编辑与高级编辑共享同一份未保存内容；未修改的元数据、自定义章节和链接原样保留。不能安全映射的复杂文档会保留原文并提示使用高级编辑，不会擅自重建。高级编辑保留原始 Markdown 编辑、导入和安全文本预览。海克斯资料可新建和删除，新建编号自动生成；导入新海克斯时按文件内的合法编号定位，但不会静默覆盖已有资料。英雄资料禁止删除。

资料状态显示为“待核实 / 已整理 / 已过时”，仅是维护标记；“已整理”不代表自动核验，“已过时”也不会自动排除检索。切换分类、对象或页面，以及正常完全退出前，会保护未保存的编辑；保存失败时保留输入以便重试。

文档路径采用 `champions/ahri.md` 或 `augments/custom-example.md`；身份字段和路径必须符合校验规则。每份文档保存时最多保留 3 份备份。种子升级只更新内容仍与旧生成版本精确匹配的文档，保留用户编辑和删除。

当前种子覆盖 173 位英雄和 211 个海克斯，另附虚构模板。**种子均未经游戏内核验，英雄技能与交互机制仍不完整。** 文档格式、必填字段和章节约定见 [OKF Profile](knowledge-seed/README.md)。

分析按英雄、候选和已选海克斯精确检索，并沿一层文档链接补充，最多提供 16 份文档、64 KiB 内容。超预算时按章节裁剪；缺失、版本差异、裁剪及不可读取的文档会显示提示。

知识正文作为模型本次判断的参考，不会被编译为固定适配分。编辑或保存知识不会自动调用收费模型；下一次手动分析或满足自动推荐条件的分析会读取更新。局势、装备或知识变化以及侧栏重开都不会额外触发自动请求。

自动推荐只在新一组完整三张候选连续两次识别稳定后触发。同一组候选在本次运行中不自动重复请求，失败也不自动重试；本次应用运行中每轮最多 3 次自动请求，与手动分析共用每日总上限。模型分析期间，实时采集与候选识别继续，不会并发发起自动模型请求；过时的分析结果不会作为当前候选推荐弹回侧栏。需要重新分析时可手动操作，仍受请求防抖及每日上限约束。关闭自动推荐立即停止新的自动调用；已发出的请求可能仍产生费用。自动推荐不会操作游戏或替玩家选择。

## 模型与隐私

支持 TypeSafe Jev 和 OpenAI 兼容服务，包括第三方 HTTPS 服务，以及 Ollama、LM Studio 等本机 HTTP 服务。连接测试读取模型列表，实际推理能力需要通过分析请求确认。使用第三方 Jev 地址需在设置中明确允许。

- API Key 按协议与服务地址保存在当前 Windows 用户的凭据管理器中，启动或切回服务时自动恢复；不写入普通设置、档案或日志。输入后自动保存，清空输入框删除该服务保存的密钥，保存状态会显示在设置页。正常升级沿用同一份凭据；地址和模型等非敏感设置也可持久化。
- 外发前去除原始 Live、LCU 和结算数据、玩家名称与对局 ID；保留英雄、海克斯、相关知识及历史观察。自由文本可能含个人信息，发送前请检查。
- 模型请求最多 256 KiB 上下文、1 MiB 响应，超时时间 30 秒。
- 同时只允许一次分析，两次分析至少间隔 8 秒；每日上限默认 20 次，可设为 1–500 次。已发出的请求计入次数，包括失败请求。
- 应用没有遥测、远程字体或云端回退。模型服务可能产生费用；本地服务是否联网由该服务自身决定。

严格离线使用需要准备本地推理服务与依赖，并限制该服务的出站网络。应用的回环地址限制不能阻止模型服务自行转发数据。

## 档案与日志

档案保存在应用数据目录的 `sessions.sqlite3`，运行日志页显示实际路径。应用标识为 `ai.hexglow.desktop`。数据库未额外加密，备份和共享时请注意玩家信息。

每页显示 50 条轻量摘要，完整档案按需读取。记录包含阵容、候选、推荐结果及当时的决策上下文、实际选择、阶段时间线、原始采样、赛果证据和复盘。接口没有提供的字段保持未知。

设置页可查看存储用量和执行维护：默认预算 128 MB，可设 32–2048 MB；原始采样默认保留 7 天，可设 1–365 天，每局最多 30 份。空闲时每 30 分钟检查维护，优先清理过期采样与旧原始快照，决策证据、选择和复盘不自动删除。预算是写入保护，不是严格的物理文件大小上限。

常规自动落盘间隔为 60 秒，阶段变化和对局结束会及时保存；异常退出可能丢失最近约一分钟的未落盘采样。异常档案单独隔离并提示，全部历史导出会保留其原文。导出文件写入应用数据目录的 `exports/`，界面显示完整路径。

运行日志采用脱敏 JSONL，不记录令牌、玩家姓名或模型上下文，当前与上一份日志合计最多 1 MiB。识别统计区分真实截屏与开发样本，不统计相同画面的缓存复用和跳过的截屏。

## 本地开发

需要 Node.js 22.13 或更新版本、pnpm 11、Rust、Windows MSVC C++ 工具链与 WebView2。CI 使用 Node.js 22.x 和 pnpm 11.7.0。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm prepare:ocr
pnpm tauri dev
```

构建和检查：

```sh
pnpm build
pnpm test
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

`pnpm prepare:ocr` 按已提交的 [模型清单](src-tauri/resources/ocr/manifest.json)准备约 31 MB 的模型和字典，逐文件校验 SHA-256 和大小。开发构建与测试从仓库资源目录加载；安装版从安装资源目录加载，不依赖 `~/.oar`、工作目录或运行时下载。模型遵循 Apache-2.0，许可与归属声明随包分发。

## Windows 打包与发布

当前版本为 **0.0.2**。版本号需同步维护 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 中的应用包，以及 `src-tauri/tauri.conf.json`。

已启用更新签名产物。构建前配置 `TAURI_SIGNING_PRIVATE_KEY`，需要密码时同时配置 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，然后运行：

```sh
pnpm verify:release
pnpm tauri build --bundles nsis
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/make-latest-json.ps1
```

可执行文件位于 `src-tauri/target/release/Hexglow.exe`；安装器位于 `src-tauri/target/release/bundle/nsis/Hexglow_0.0.2_x64-setup.exe`。安装器为当前用户安装，提供中英文语言选择；WebView2 缺失时会下载引导程序。

安装前通过托盘退出已运行的 Hexglow，再运行安装器。覆盖安装与卸载会保留应用数据目录中的知识库、对局记录和设置；不要手动删除该目录。OCR 模型包含在安装包内，模型文件缺失或损坏时请重装完整安装包。单独复制 `Hexglow.exe` 不是完整安装方式。

更新采用 `tauri-plugin-updater`，构建生成安装包和 `.sig`，由 `scripts/make-latest-json.ps1` 生成 UTF-8 无 BOM 的 `latest.json`。`.sig` 用于更新校验，安装器未做 Authenticode 代码签名。

发布预检核对四处版本、OCR 哈希与资源映射；生成更新清单前，使用应用内公钥验证安装器及签名元数据，并生成 `SHA256SUMS.txt`。安装后可用 `scripts/verify-installed.ps1 -InstallDirectory <安装目录>` 检查 GUI 子系统、版本和随包模型。已公开发布的同版本附件不应覆盖，工作流对此直接报错。

[Windows 工作流](.github/workflows/windows.yml)在 PR 中执行构建与测试；推送执行签名构建，推送与当前版本一致的 `v<版本>` 标签后发布 GitHub Release。仓库需配置签名 secrets；私钥不得提交。更新端点为 `https://github.com/mrone0/Hexglow/releases/latest/download/latest.json`，需要公开可访问的 Release 和附件。

## 已知限制

- OCR 依赖画面布局、语言和识别质量；只在游戏前台截屏，切换应用或最小化时跳过。
- LCU 和 Live API 随客户端版本变化，可能出现接口不可用或信息不完整。
- 打包数据、知识机制和模型置信度尚未经过系统性的游戏内校准，推荐仅供参考。
- 长期运行稳定性、真实模型服务和完整选卡流程仍需持续验证。

应用只读本地 API 和屏幕，不读取游戏内存、不自动点击、不绕过保护，也不展示海克斯聚合胜率。使用和发布前请阅读 [Riot 官方开发者支持说明](https://support-developer.riotgames.com/hc/en-us/articles/22698698001939-League-of-Legends)，核验产品用途与相关要求；项目没有 Riot 背书。
